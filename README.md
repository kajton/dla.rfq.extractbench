# dla-rfq-parser

A Python CLI and benchmark for extracting procurement fields from DLA and
SAM.gov RFQ PDFs. The repository includes synthetic sample PDFs and matching
ground-truth JSON files.

## Setup

Install dependencies:

```bash
python -m pip install -r requirements.txt
```

Python 3.10 or newer is required.

Set `GEMINI_API_KEY` in the project-root `.env` file or in your environment
before using hybrid extraction. The CLI uses Google's `gemini-3.8-flash` by
default. Keep `.env` private; it is excluded by `.gitignore`.

The `.env` file should contain:

```dotenv
GEMINI_API_KEY=your_api_key
```

Generate the synthetic fixtures and run the offline regex benchmark:

```bash
python generate_samples.py
python benchmark.py
```

Run the hybrid benchmark or compare it with the regex baseline:

```bash
python benchmark.py --mode hybrid-llm
python benchmark.py --mode compare
```

Extract a single PDF:

```bash
python extractor.py path/to/solicitation.pdf --output extraction.json
python extractor.py path/to/solicitation.pdf --regex-only
```

The benchmark writes `benchmark_report.md`. It scores fields only when a
same-named JSON reference exists in `ground_truth/`; without references, the
report shows populated-field counts, not accuracy.

## Design and limitations

- `pdfplumber` extracts page text and tables. PyMuPDF supplies fallback text
  and helps flag image-heavy pages with little embedded text.
- Regex matches provide anchors for solicitation numbers, NSNs, MIL-STD
  packaging codes, and common labeled fields.
- Gemini returns a Pydantic-validated structured extraction. The regex-only
  mode does not require an API key.
- The benchmark reports exact field matches, compliance flags, latency, and
  detected failure modes.

RFQs may have scanned pages, split identifiers, continuation rows, or
multi-column layouts that are linearized incorrectly during PDF extraction.
The parser flags some low-text and irregular-table cases, but does not perform
OCR or guarantee that table cells are aligned correctly. Review results
against the source PDF before relying on them.

The three PDFs generated by `generate_samples.py` are synthetic. The benchmark
also reads any other `*.pdf` files in `sample_rfqs/`. Store real solicitations
and extracted outputs locally unless you have confirmed they are appropriate
to share.
